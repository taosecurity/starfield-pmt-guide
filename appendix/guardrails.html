Appendix

Guardrails for AI use

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

This page lists the rules to keep when an AI agent runs PMT tools for you. The main ones are never sharing game code, making the agent ask before it changes anything or sends anything out, and checking every claim against the tool's own report. It also explains what an agent's service can see.

On this page
  • Never share game code
  • Ask before changing anything
  • Check every claim
  • The agent can't play the game
  • Privacy

These rules apply to every agent, and to you. The starfield-agent plugin enforces some of them with two guards, but other agents follow only what you tell them and what each tool's AGENTS.md says.

Never share game code

  • Never put game code in a message to an agent, a repository, a release, an issue or a post. That means game executables, decompiled code, extracted game files and official script source (.psc files from Bethesda).
  • Share symbol names, record names and descriptions of formats instead.
  • Never publish the output of sf-papyrus-ref html, its local cache, or anything unpacked with ba2_extract.py. They hold Bethesda's content.
  • starfield-agent's game-code guard refuses git add, git commit, git push and some gh upload commands that would carry such files. Don't turn it off to finish a task.

Ask before changing anything

  • The agent asks before it changes a load order, Plugins.txt, the game's Data folder or your saves. The PMT checking tools only read and report, and you apply any suggested change yourself, after a backup.
  • The agent asks before any upload, push, release or post. Uploading to Nexus Mods or Creations is always your step.
  • The agent asks permission before it changes another author's mod, and you keep the author's reply.
  • starfield-agent's game guard refuses changes to the Data folder, the saves folder, Plugins.txt and ContentCatalog.txt. Never disable a guard to get a task done. If a guard refuses something it should allow, report it (see Report a problem).

Check every claim

  • Ask for the report line behind each claim: the RESULT: line, the exit code or the report file and line.
  • An exit code of 0 doesn't mean a save or a mod is safe. Read what the report says it did not check.
  • Triage shows where to start reading. It never says a mod is safe or unsafe, and an agent must not say so either.
  • Look up Papyrus function names with sf-papyrus-ref instead of trusting the agent's memory.

The agent can't play the game

  • An agent can't launch Starfield and play it, and it can't see your screen unless you share one.
  • You play, you mark each test step and you tell the agent what happened. The agent reads the logs afterward.
  • Console testing is by hand.

Privacy

  • The PMT tools make no network calls. The agent's service does see what the agent reads: file names, report text and log text.
  • Don't let the agent read what you wouldn't share. Logs and reports can hold your Windows user name, your computer name and your folder names.
  • Where a tool has --redact (sf-save-health and sf-save-reader do), add it to any run whose output will leave your PC. In sf-save-health it hides the character name, the Windows user, the computer name and the profile folder. In sf-save-reader it hides the player name and the save's file name. Plugin names and quest names stay in both.
  • sf-log-collector redacts only when you add -Redact (or answer yes when the double-click run asks). Even then, saves, screenshots and file names stay as they are. Open the zip and read it before you post it or let an agent read it.
  • Keep backups of anything an agent might change, and keep your own permission records.
  • Read your own logs and reports before posting them anywhere.
