Appendix

Report a problem with a tool

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

This page says how to report a problem with a PMT tool. Open an issue on that tool's GitHub repository, and include the tool version, the exact command, the exit code and the log file. Remove personal data from everything before you post it.

On this page
  • What to include
  • Remove personal data first
  • If you use an agent
  • Reporting a problem with someone else's tool

Each PMT tool has its own repository at https://github.com/taosecurity/<tool name>, for example https://github.com/taosecurity/sf-load-order. Open an issue on the repository of the tool that has the problem, using its Issues tab.

If you are not sure which tool is at fault, use the repository of the first tool in your command. Check the tool's README first, because some behavior is by design.

What to include

  • The tool and its version. Most tools print it with --version. You can also use the version in the release name.
  • The exact command, with any file names changed to stand-ins such as MyMod.esm.
  • The exit code and the RESULT: line, if the tool printed one.
  • Your setup: Steam or Game Pass, Vortex, MO2 or no manager, and the Starfield version.
  • The log file. Run the command again with --verbose or --log <file>, then attach the file. Most PMT tools take these options, and each tool's AGENTS.md says to use them for troubleshooting. For a tool that has no such option, see its README.
  • What you expected and what happened.

Example of a command with a log:

Command Prompt
sf-mod-check check MyMod.esm --log sf-mod-check.log

Remove personal data first

Warning

Logs, reports and zips can hold your Windows user name, your computer name, your folder names and your character name. Read every file before you attach it.

  1. Open the log or report in a text editor and search for your Windows user name and your computer name. Replace each with USER or PC.
  2. For saves, add --redact to the sf-save-health or sf-save-reader command when you create the report that you attach.
  3. Don't attach a save file, a plugin you don't own or any of the game's files. Never attach game code or official script source.
  4. A zip from sf-log-collector is redacted only when you made it with -Redact, and even then saves, screenshots and file names stay as they are. Open it and read the files inside before you attach it, or paste only the lines that matter.
  5. Show the exact error line instead of a whole file when you can.

If you use an agent

Ask the agent to draft the issue, then read it yourself before it is posted. The agent must not post it for you, because posting is your step. See Guardrails for AI use.

Reporting a problem with someone else's tool

For tools in Other free tools, use that tool's own issue tracker. Before you report what looks like a bug, make sure your own setup isn't the cause, read the author's docs and existing issues, and give steps that reproduce it.
