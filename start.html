Getting started

Getting started

Do this with an agent

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

This page shows how to install the PMT tools you need, check each download, and prove each one works. It also says where the tools look for files on Steam, Game Pass, Vortex, Mod Organizer 2 and Creations setups, and what they read, write and never send. You only need the tools for the jobs you want to do.

What you need

  • A Windows PC with Starfield. PMT tools run on a PC. Some also run on Linux. No tool runs on a console.
  • Python. Most tools need Python 3.9 or newer. sf-test-plan needs 3.10 or newer, and some tools on Linux need 3.10 or newer. When you install Python, tick "Add python.exe to PATH".
  • .NET. sf-save-health and sf-save-reader need the .NET 9 runtime or later. sf-mod-build and BuildKit need the .NET 9 SDK or later. sf-mod-check comes as a single exe with .NET built in.
  • The Starfield Creation Kit from Steam. sf-mod-build needs it, and sf-papyrus-ref uses it for function signatures. It provides PapyrusCompiler.exe, Archive2.exe and ContentResources.zip. The Creation Kit exists only on Steam.
  • PowerShell. sf-log-collector needs Windows PowerShell 5.1 (built in) or PowerShell 7.
  • A folder for each tool. Unpack each tool into its own empty folder.

You don't need every tool. Part 1 and Part 2 say which tools each page uses.

Download and check each release

Every tool is a free download from the Releases page of its GitHub repository, at https://github.com/taosecurity/<tool name>/releases. Each release has a .sha256 file (sf-mod-build uses SHA256SUMS). Check your download against it before you open it:

Command Prompt
certutil -hashfile sf-load-order-0.3.2.zip SHA256

Compare the long number that prints with the number in the .sha256 file. If they differ, delete the download and get it again.

sf-mod-check is also on nuget.org (since version 0.18.0). If you have the .NET SDK 9 or later, this installs it with no download, on Windows or Linux:

Command Prompt
dotnet tool install --global sf-mod-check

dotnet tool update --global sf-mod-check installs a newer version later. sf-mod-build can install as a .NET tool too, from its release's .nupkg file, with dotnet tool install --global sf-mod-build --add-source . in the folder that holds it, if you prefer.

BuildKit is a library for C# programs. Add it to a console project:

Command Prompt
dotnet add package Taosecurity.Starfield.BuildKit --version 0.6.1

For sf-mod-build's starter template, unzip sf-mod-build-template-0.5.1.zip, then install the template:

Command Prompt
dotnet new install <folder>

SmartScreen

The exe files, such as sf-cut-check's, are unsigned. If Windows SmartScreen warns you, choose More info, then Run anyway. Only do this for a download whose checksum matched.

For sf-mod-check, you can also run sf-mod-check check MyMod.esm on a plugin of your own. It ends with a RESULT: line.

To prove sf-log-collector on your own PC without zipping real logs, use the dry run:

PowerShell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Collect-StarfieldTestLogs.ps1 -NoPrompt -DryRun

It prints Done. and the path where a zip would go. If Starfield has never run under your Windows account, it also warns that Documents\My Games\Starfield was not found, because the game makes that folder the first time it starts. Start the game once, or give the folder with -MyGamesDir.

Where the tools look for files

SetupWhat to know
SteamAutomatic for almost every tool. The default Data folder is C:\Program Files (x86)\Steam\steamapps\common\Starfield\Data. Steam saves are in Documents\My Games\Starfield\Saves.
Game PassThe Data folder is <drive>:\XboxGames\Starfield\Content\Data. Most tools find it. Pass --data when one doesn't. Saves are in an Xbox container and must be exported to .sfs files first. The Creation Kit exists only on Steam, so sf-mod-build builds on Steam. SFSE doesn't support Game Pass.
VortexVortex deploys into the real Data folder, so the checking tools work as they are. For a load order, deploy in Vortex and run sf-load-order on the Plugins.txt that Vortex writes.
Mod Organizer 2 (MO2)sf-load-order reads an MO2 profile. For sf-save-health and sf-save-reader, add the exe as an MO2 executable and run it from MO2. sf-mod-check's conflict, patch and find take --mo2 <instance> [--profile <name>] (0.16.0 and later), so they see MO2's mods, and sf-load-order (version 0.3.2 and later) hands its --mo2 instance and profile to sf-mod-check for its record check. sf-mod-check and sf-cut-check take --data for the real Data folder. MO2 2.5.2 is the last stable release. It treats Shattered Space and Terran Armada as ordinary plugins, so check that they stay ticked in its plugin list. The 2.5.3 betas pin them at the top (details).
No managerThe default run reads the game's own Plugins.txt at %LOCALAPPDATA%\Starfield\Plugins.txt.
CreationsCreations are ordinary plugins in Data and in Plugins.txt, so the tools read them like any plugin.

Papyrus logging goes into StarfieldCustom.ini in Documents\My Games\Starfield. Vortex doesn't move that file. If your MO2 profile uses profile-specific INI files, edit the profile's copy.

What the tools read, write and never send

The tools read local files and write reports where you point them, and none of them uploads anything. The tools with a PRIVACY.md say they make no network calls.

  • Every tool has a PRIVACY.md that says what it reads, what it writes and that it never sends anything. Eleven are in the tagged releases: sf-mod-check, sf-load-order, sf-log-collector, sf-mod-build, sf-papyrus-ref, papyrus-log-check, sf-test-plan, sf-patch-day, sf-pex-tools, sf-cut-check and BuildKit. The other four have it on their main branch, ahead of their next release: sf-save-health, sf-save-reader, StarfieldVoiceTool and starfield-agent.
  • sf-mod-build never uploads and never writes in the game folder. It makes no network connections of its own. It starts the programs your project names, and dotnet downloads the builder's NuGet packages on the first build. It runs the commands in your sfmod.json, so only build projects you trust.
  • sf-save-health and sf-save-reader have --redact. In sf-save-health it hides your character name, Windows user name, computer name and profile folder. In sf-save-reader it replaces the player name and the save's file name with (redacted). Plugin names and quest names stay in both.
  • sf-log-collector has -Redact, which hides your Windows user name, computer name, user folder and Steam account number in the text files it copies. Saves, screenshots and file names stay as they are.
  • starfield-agent makes no network calls of its own, but the AI agent you use does talk to its own service. See Set up an AI agent.
Warning

Logs, reports and zips can hold your Windows user name, your computer name and folder paths. Read them before you post them. Without -Redact or --redact, nothing is hidden.

Limits to know

  • The tools run on a PC. Windows comes first, and some also run on Linux.
  • The save tools read only saves from Starfield 1.16.244. A game update can stop them until they are updated. Run .\sf-patch-day.cmd dlls after an update.
  • The tools only read and report. The builders, sf-mod-build and BuildKit, write your own mod's files and nothing else.
  • Nothing here uploads. Uploading to Nexus Mods or Creations is your own step.
