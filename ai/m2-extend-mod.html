Part 2: For modders

Extend another author's mod with an agent

Do this by hand

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

Your agent can plan and build an add-on plugin that uses another author's mod as a master, and run every check with the master's folder given. It asks about permission first, and you keep the author's reply. Whether to build, and whether to release, stays your decision.

On this page
  • What to ask
  • What the agent runs
  • What you check
  • What stays your decision
  • For CK and xEdit authors
  • For code builders

What to ask

Ask your agent
I want to add new NPC types to a spawner mod by another author. Before you build anything, tell me what permission I need and what I should keep.
Ask your agent
Make an add-on plugin that uses the original as a master and adds my own records without changing theirs. Use a prefix and stable IDs.
Ask your agent
Check the add-on against the other author's folder and tell me each RESULT line and exit code.

What the agent runs

The starfield-agent skill rebuild-mod asks about permission first, and the skill build-mod builds and checks. Other agents follow sf-mod-build's AGENTS.md and sf-mod-check's AGENTS.md, which tell them to use --masters-dir for add-ons. The commands match the manual page.

Command Prompt
sf-mod-build build --masters-dir <folder of OtherMod>
Command Prompt
sf-mod-build check --masters-dir <folder of OtherMod>
Command Prompt
sf-mod-check check MyMod.esm --masters-dir <folder of OtherMod>
Command Prompt
sf-mod-check gap MyMod.esm --masters-dir <folder of OtherMod>
Command Prompt
sf-mod-check release MyMod-0.1.0.zip --masters-dir <folder of OtherMod> --master-archive "<folder of OtherMod>\OtherMod - Main.ba2"
Command Prompt
sf-cut-check scan --plugin MyMod.esm --masters-dir <folder of OtherMod>

To read the conversations of one of the other author's NPCs or quests before it builds, the agent can use scenes (since sf-mod-check 0.24.0, released 2026-11-26). It prints the conversations as a tree, one section per scene, with a table of the player's choices and where each leads. It changes nothing. The agent can run it again on your own quest to find broken jumps and choices with no way out.

Command Prompt
sf-mod-check scenes OM_Quest --plugin "<folder of OtherMod>\OtherMod.esm"

check with --masters-dir also reads the add-on's own archive, so its own scripts count as found (sf-mod-check 0.16.2 or newer). --master-archive takes the archive's full path. Both build and check take --masters-dir, once per folder. For the builder code, the worked example "An add-on for another author's mod" is in BuildKit's README, section "More examples" (back since BuildKit version 0.6.1, after the 0.6.0 README dropped it). If the builder writes a second plugin, the agent lists it in parts, and sf-mod-build (since version 0.5.0) writes one zip per plugin and checks each one.

What you check

  • Permission. Ask the agent what it found about permission, then read the mod page yourself. The agent can't ask the author for you.
  • Add, not change. Ask the agent to list every record the add-on changes. The answer should be none of the original's records.
  • The RESULT lines and exit codes of check, gap and release.
  • Stable IDs. The agent should commit ids.lock.json with the builder.
  • Orphaned or Unreferenced from sf-cut-check means "nothing in the plugins uses it", not proof that a record is dead.

What stays your decision

  • Whether to extend this mod at all, and whether the author agrees. You keep the reply.
  • How to credit the author in the README.
  • Whether to release the add-on, and the upload to Nexus Mods or Creations.
  • Whether a record the add-on adds is worth keeping.

For CK and xEdit authors

The agent can run the checks with the master's folder, explain each finding and draft the README credits. It can't open the CK or xEdit, so you load the master and make the records.

For code builders

The agent can write the builder: open the master with GameData, call IdLock.Apply, write the plugin with BuildKit, and build. Tell it to ask about permission before it starts, and review the builder before you keep it.

Read the guardrails before you let an agent act on your files.
