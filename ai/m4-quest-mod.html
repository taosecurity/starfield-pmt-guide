Part 2: For modders

Build a quest mod with an agent

Do this by hand

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

Describe the quest's stages, objectives and alias in plain words, and your agent writes the scripts and the quest records, builds the mod, runs the checks and writes a test plan with a check for each stage. You decide the story, play each stage, and confirm the quest really finishes. The agent must say that it wrote the quest records with plain Mutagen, and it must run the gap check on them.

On this page
  • What to ask
  • What the agent runs
  • What you check
  • What stays your decision
  • For CK and xEdit authors
  • For code builders

What to ask

Ask your agent
Make a new quest mod called PMTTutorialCourier with the prefix PTCR. Three stages: when I first arrive in New Atlantis, give me a note and show "Read the courier's note"; when I read it, show "Collect 5 Iron"; when I hold 5 Iron, pay 100 credits, complete the quest and show a HUD message. One player alias, no dialogue or voice, no changes to vanilla records, and the Xbox archives.
Ask your agent
Make sure the quest finishes properly: call Stop() after CompleteQuest() at the last stage, and flag that stage's journal entry Complete Quest. Show me where you did both.
Ask your agent
Write a test plan with one group per stage and the getstage and setstage console commands, and a rule file for the stage log lines. After my test, read the quest from my save and tell me its state.

What the agent runs

The starfield-agent skills new-mod, build-mod, logging-rules and test-plan cover this task. Other agents follow each tool's AGENTS.md: sf-mod-build, BuildKit, sf-mod-check, sf-papyrus-ref, sf-cut-check, sf-test-plan and sf-save-reader. The commands match the manual page, where each one is explained.

Command Prompt
dotnet new sfmod -n PMTTutorialCourier --prefix PTCR --mod-author "PMT Guide"
cd PMTTutorialCourier
sf-mod-build doctor
Command Prompt
sf-papyrus-ref lookup Quest.SetStage
sf-papyrus-ref lookup Quest.Stop
sf-mod-check find CityNewAtlantisLocation
sf-mod-check find InorgCommonIron
Command Prompt
sf-mod-build validate
sf-mod-build build
Command Prompt
sf-mod-check check dist\PMTTutorialCourier.esm
sf-mod-check gap dist\PMTTutorialCourier.esm
sf-mod-check find --plugin dist\PMTTutorialCourier.esm
sf-papyrus-ref check Scripts --creations
sf-mod-check release creations-out --profile creations
sf-cut-check scan --plugin dist\PMTTutorialCourier.esm --out C:\Scratch\cutcheck-cr
Command Prompt
sf-test-plan new PMTTutorialCourier.testplan.md --mod PMTTutorialCourier
sf-test-plan rules PMTTutorialCourier.testplan.md --prefix PTCR --plugin PMTTutorialCourier.esm
sf-test-plan check PMTTutorialCourier.testplan.md --rules PMTTutorialCourier.logrules.json
sf-test-plan build PMTTutorialCourier.testplan.md --rules PMTTutorialCourier.logrules.json
Command Prompt
sf-save-reader quests <save.sfs> --data --filter PTCR --details

find --plugin lists the quest's alias and one line per stage, but not the log entries' flags, so it can't confirm the Complete Quest flag. In the tutorial's 0.1.1 test, sf-save-reader read the quest as "stopped, completed, stage 30". rules writes a rule only for each log: id in the plan, so the agent adds those lines first, and release creations-out needs "xbox": true in sfmod.json. The tutorial's source, with its WALKTHROUGH.md, is in the folder examples/PMTTutorialCourier/ of this guide's repository (https://github.com/taosecurity/starfield-pmt-guide).

BuildKit has no helpers for stages, objectives or aliases, so the agent writes them with plain Mutagen next to BuildKit's Quests.New. It must tell you so, and it must run sf-mod-check gap on the plugin, because gap finds data that Mutagen loses when it writes records.

What you check

  • The quest finishes. Ask the agent to show the last stage's script lines (CompleteQuest(), then Stop()) and the journal entry's Complete Quest flag. Without both, the quest never shows under Missions > Completed. After your test, the save should read "stopped, completed", not "running, completed".
  • Every stage the scripts set exists. No tool checks this. Ask the agent to list the stages in the plugin and every SetStage() call in the scripts, side by side.
  • Every Papyrus name was looked up. A name that lookup didn't find must not be in a script unless the agent can show where it is defined.
  • The RESULT lines and exit codes of check, gap, release creations-out --profile creations and sf-test-plan check. Ask for the exact lines.
  • The rule file. rules only guesses patterns. Check that each one matches the real [PTCR] line and that no-script-errors is under forbid.

What stays your decision

  • The story, the stage numbers, the reward and every line of player text.
  • Playing each stage on a new character and marking the plan. The agent drafts results from the log and the save, but only you saw the Missions menu.
  • Voice: recording lines and making voice files in the Creation Kit, if your quest has dialogue. Nothing flags a line with no voice file, so you listen to each one.
  • Console testing, by hand on the console, and the upload, which the Creation Kit does. The agent never uploads.

For CK and xEdit authors

The agent can't drive the CK's window. You build the stages, objectives and aliases in the CK, which is the normal route for quests. The agent can write and check the stage scripts, remind you to call Stop() and tick the Complete Quest checkbox on the last stage's log entry in the CK, run every check on the CK's plugin, and write the test plan and rule file.

For code builders

The agent can write the whole quest with BuildKit and plain Mutagen, as the tutorial's Program.cs does. Check that it said which records it wrote with plain Mutagen, ran gap after the build, kept ids.lock.json, and set QuestLogEntry.Flag.CompleteQuest on the last stage's entry.

Read the guardrails before you let an agent act on your files.
