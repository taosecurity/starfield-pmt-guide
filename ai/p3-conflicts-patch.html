Part 2: For players

Find conflicts and build a patch with an agent

Do this by hand

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

Your agent runs the conflict report, explains it in plain words and proposes which mod should win each important record. It can build the patch, but you choose the winners. The patch is for your game only and is never published.

On this page
  • What to ask
  • What the agent runs
  • What you check
  • What stays your decision

What to ask

Ask your agent
Run the conflict report for my load order and explain the conflicts that matter most.
Ask your agent
Two of my mods change the same item. Show me both versions and suggest which one should win, but let me decide.
Ask your agent
Build a conflict patch with the winners I chose, then tell me exactly how to load it last.

What the agent runs

No starfield-agent skill covers this task. The agent follows sf-mod-check's AGENTS.md and sf-load-order's AGENTS.md, and so do other agents. The commands match the manual page.

Command Prompt
sf-mod-check conflict

Under MO2, the agent adds your instance (conflict, patch and find take --mo2 <instance folder> and --profile <name> in sf-mod-check 0.16.0 and later):

Command Prompt
sf-mod-check conflict --mo2 "<instance folder>" --profile "<profile name>"

To look at one record in your load order:

Command Prompt
sf-mod-check find <EditorID>
Command Prompt
.\sf-load-order.cmd
Command Prompt
sf-mod-check patch

With a limited list of plugins, and with your chosen winners:

Command Prompt
sf-mod-check patch --only MyMod.esm,OtherMod.esm
Command Prompt
sf-mod-check patch --pick 064F3C:Starfield.esm=OtherMod.esm

Each --pick is a FormKey, an equals sign and the plugin that should win, and patch-report.md prints ready-made lines to copy. The plugins named with --only and --pick must be active in your load order, or the run stops with exit 2. The patch goes into the folder sf-mod-check-patch unless the agent gives --out.

After any mod changes, on the installed patch:

Command Prompt
sf-mod-check patch check "<path to>\ConflictPatch.esm"

What you check

  • The report. Open report.html and look at the records the agent calls important. Ask it to point to each one.
  • The winners. The agent proposes --pick choices. Check each pick names the plugin you want.
  • Patch check. RESULT: REBUILD means the patch is out of date. If the agent says the patch is fine, confirm it with the RESULT: line from patch check. A line that ends (the patch isn't in the load order; nothing was checked) means nothing was checked, even though it starts with UP TO DATE.
  • MO2. Under Mod Organizer 2, the agent must pass --mo2 (and --profile) to conflict, patch and find. Without it the report sees only the real Data folder. MO2 support was tested on made-up MO2 folders, so ask the agent to quote the report's load-order line (MO2 profile <name> (<folder>), <n> active entries) and its load-order problems the first time. With --mo2, the patch report says to add the patch in MO2 with Create empty mod, which you do yourself.
  • Quests and dialogue. The patch doesn't build those records. The agent should list them for xEdit rather than claim they are fixed.

What stays your decision

  • Which mod wins each conflict. The agent suggests, and you choose.
  • Installing ConflictPatch.esm and placing it last in your load order.
  • Keeping the patch private. It holds other authors' data, so the agent must never publish, share or upload it, and you shouldn't either.
  • Whether to use xEdit for quest and dialogue records, and doing that work, since an agent can't drive xEdit's window.

Read the guardrails before you let an agent act on your files.
