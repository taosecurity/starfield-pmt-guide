Part 2: For players

Evaluate a mod with an agent

Do this by hand

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

Your agent runs triage on a download, checks which files it shares with your installed mods, and explains what it found in plain words. The agent never calls a mod safe or unsafe from triage alone. You read the mod page and decide whether to install it.

On this page
  • What to ask
  • What the agent runs
  • What you check
  • What stays your decision

What to ask

Ask your agent
Evaluate SomeMod-1.2.0.zip before I install it. Tell me where I should start reading, and which files it shares with the mods I already have.
Ask your agent
I installed SomeMod. Check my load order and the record conflicts, and tell me which findings come from this mod.
Ask your agent
SomeMod has a new version. Compare 1.1.0 with 1.2.0 and tell me what changed.

What the agent runs

The starfield-agent skill evaluate-mod covers this task. Other agents follow sf-mod-check's AGENTS.md and sf-load-order's AGENTS.md. Both say to run the commands exactly as listed and to quote the RESULT: lines and exit codes.

Command Prompt
sf-mod-check triage SomeMod-1.2.0.zip

Since sf-mod-check 0.17.0 (released 2026-11-24), triage lists every changed field of each official record the mod overrides. Each record shows at most 200 rows, plus up to 200 more for the two translation kinds, and each value is cut at 2,000 characters. The whole report holds at most 10,000 rows, with real changes first. Each cut says how much it left out. The agent should tell you that the rows "same entries, other order" (a list in a new order) and "same English text, translations dropped" (English unchanged, other languages not carried) are often harmless, and point you to the other rows first.

Command Prompt
.\sf-load-order.cmd candidate SomeMod-1.2.0.zip

candidate reads .zip, .7z and .rar downloads (7-Zip must be installed for the last two). It also compares records. At the default depth it runs sf-mod-check conflict on your load order with the download added, so it takes as long as one conflict run, about 2 minutes on a 150-plugin load order. The agent should say so and let it finish.

To say what the download does before you install it, the agent runs summary (sf-mod-check 0.26.0 and later). It takes the zip, 7z or rar as it is and deletes its temporary unpacked copy when it ends. It lists the masters, the records added and overridden per type, the fields the overrides change, the cells touched and the kinds of objects placed. To read the records, find --plugin takes the zip too:

Command Prompt
sf-mod-check summary SomeMod-1.2.0.zip
Command Prompt
sf-mod-check find --plugin SomeMod-1.2.0.zip --masters-dir "<folder of a required mod>"

After you install the mod:

Command Prompt
.\sf-load-order.cmd
Command Prompt
sf-mod-check conflict

For an update:

Command Prompt
sf-mod-check diff SomeMod-1.1.0.zip SomeMod-1.2.0.zip

For a Creation, after the game has installed it:

Command Prompt
sf-mod-check check OtherMod.esm

The commands are explained on the manual page.

What you check

  • Triage wording. Every finding should be a NOTE or a LOOK. If the agent says the mod is safe, unsafe, clean or good, it went past what triage can say.
  • The reports. Open the .txt or .html triage file and read the LOOK lines yourself.
  • Exit codes and RESULT: lines. Check them against what the agent reports. For diff, 0 means no differences and 1 means differences.
  • The record check. candidate reports one caution per installed mod whose records the download also changes, or a caution that the record check didn't run (no sf-mod-check, no Data folder, a Vortex profile that isn't deployed, or MO2 started from outside MO2). At --depth light it doesn't check records at all. If the agent says the mod has no conflicts, ask which of these it saw, and whether it ran sf-mod-check conflict after installing.
  • The summary. summary reports what the plugin changes, not whether the change is good. A missing master stops a single-plugin run with exit 2, and the agent should then add --masters-dir with the folder of the required mod. Only in a download with several plugins is the one plugin whose master is missing left out with a note, so ask the agent whether every plugin was summarized.
  • Run-time behavior. Triage can't see what a DLL or script does when the game runs. The agent can't either.

What stays your decision

  • Reading the mod page, its requirements and its permissions.
  • Judging quality and whether to trust the author.
  • Installing the mod, and removing it again if the results are bad. For Vortex you drop the zip onto Vortex yourself.
  • Reporting a bug to an author. The agent must not do it from triage alone.
  • Installing a Creation from the in-game menu.

Read the guardrails before you let an agent act on your files.
