Part 2: For players

Check and improve a load order with an agent

Do this by hand

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

Your agent runs sf-load-order for your setup, reads report.txt and explains the Top 10 findings in plain words. It never copies a suggested file into place. You check the report, take the backup and decide what to apply.

On this page
  • What to ask
  • What the agent runs
  • What you check
  • What stays your decision

What to ask

Ask your agent
Check my load order and tell me what to fix first. I use Vortex, so I will deploy my mods first.
Ask your agent
I use MO2. Read my profile and tell me whether the suggested order is safe to apply, and what I should back up first.
Ask your agent
I only use the Creations menu. Check my load order and tell me in which order to drag my Creations.

What the agent runs

None of the twelve starfield-agent skills is only for a load order check. The skill patch-day looks at the load order after a game update, For a plain check, the agent (and any other agent) follows sf-load-order's AGENTS.md, which says to run the listed commands, read report.txt and explain the Top 10 findings. The route depends on your setup. The agent asks which one you use.

No manager:

Command Prompt
.\sf-load-order.cmd

Vortex. The default route needs no extension. The agent asks you to deploy in Vortex first, which writes the game's Plugins.txt, then runs this:

Command Prompt
.\sf-load-order.cmd

The optional route is our fork of the Vortex Modlist Backup extension (github.com/taosecurity/Vortex-Modlist-Backup), a fork of Garethp's extension with no release yet. Its toolbar button on the Mods page, "Back Up Modlist and Load Order (This Profile)", writes the load order file that --vortex-profile reads. Garethp's original backs up only the mod list. With the fork, the agent runs this:

Command Prompt
.\sf-load-order.cmd --vortex-profile "<profile name>"

MO2. Tell the agent which MO2 version you use. For Starfield, prefer the 2.5.3 beta (beta 12 was released 2026-05-23) or a later release over 2.5.2, the last stable release (2024-08-04). If you stay on 2.5.2, the agent should ask you to check that Shattered Space and Terran Armada stay ticked in MO2's plugin list after you copy a suggested order in. If StarfieldCustom.ini has sTestFile lines, MO2 turns its plugin management off in every version (details).

Command Prompt
.\sf-load-order.cmd --mo2 "<instance folder>" --profile "<profile name>"

For record conflicts between MO2 mods, the run above is enough since sf-load-order version 0.3.2: with sf-mod-check 0.16.0 or newer it starts sf-mod-check conflict --mo2 <instance folder> --profile <profile> --data <Data> itself (--verbose logs the command), so the agent no longer passes --conflicts by hand. For sf-mod-check's full report, or before a patch, the agent runs it directly:

Command Prompt
sf-mod-check conflict --mo2 "<instance folder>" --profile "<profile name>"

--depth heavy's per-plugin check, the merged-patch check and candidate's record check still need sf-load-order started from MO2. The agent should say when the record section skipped and quote its reason, for example an sf-mod-check older than 0.16.0, or a plugin sf-mod-check would load that the game drops.

Creations menu only. The agent runs the default check. HOW-TO-APPLY.txt then has a part for Creations-only players with two routes: copy the suggested plugins.txt over yours with the game closed, or move each Creation in the game's Creations menu until the list matches. The agent explains both, and you choose. A later change in Creations replaces a copied file, so pick one place to manage the order.

Command Prompt
.\sf-load-order.cmd

For a deeper check, which also runs sf-mod-check's plugin check on every enabled mod plugin:

Command Prompt
.\sf-load-order.cmd --depth heavy

A heavy run takes several seconds per plugin on top of a normal run, so it took about 14 minutes on a 150-plugin load order in this guide's test (2026-11-24), and the screen shows nothing but the tool's name until it ends. The agent should say so, let it finish, and add --log <file> if you want to watch its progress.

The commands are explained on the manual page. The reports go to a folder called sf-load-order-report, with report.txt, report.html, report.json, a suggested plugins.txt and HOW-TO-APPLY.txt. The game's own rules are in Starfield Load Order Facts.

Sort a load order

sf-load-order 0.3.2 can build a whole load order with sort. It keeps your current order wherever the rules allow, so as few plugins as possible move. It never applies the order: it writes files and a HOW-TO-APPLY.txt, and you apply them after a backup.

Command Prompt
.\sf-load-order.cmd sort

Your own rules live in sf-load-order-rules.json (by default in %LOCALAPPDATA%\sf-load-order\, or the file you give with --rules). sort writes its record-conflict choices to rules-proposed.json. rules propose writes the same file without sorting, but needs --conflicts <conflicts.json> from sf-mod-check conflict, or the file holds no choices. The agent can run rules propose and rules list, rules explain and rules check. Only you decide which proposals rules accept copies into your file. LOOT's userlist and masterlist after rules are used when the masterlist is found, LOOT's groups only with --loot-groups, and Vortex's rules are a tie-break.

What you check

  • The RESULT: line. It ends the run in the form RESULT: n problem(s), n caution(s), n note(s). The agent should quote it. If it says the load order is fine without that line, ask for it.
  • The exit code. 0 means a report was written, even with problems. 1 means problems with --strict. 2 means the tool couldn't run (RESULT: CANNOT CHECK), so nothing was checked.
  • The Top 10. Open report.txt and compare the agent's summary with the first ten findings. Make sure it didn't skip a problem.
  • The StarfieldCustom.ini caution. If the report has one, the file has sTestFile lines. The game and MO2 then skip Plugins.txt, so a suggested order won't take effect. Ask the agent to quote the caution, back up the INI, and remove the lines only with your OK.
  • The MO2 check. MO2 support in sf-mod-check was tested on made-up MO2 folders. The first time, ask the agent to quote the report's load-order line (MO2 profile <name> (<folder>), <n> active entries) and its load-order problems.
  • Your logs. The log holds your folder names. Read it before you let the agent or anyone else post it.
By design

sf-load-order sort builds an order but never applies it. Applying it is your step, and LOOT is still there if you prefer its interface and groups.

What stays your decision

  • Applying the order. The agent never copies the suggested files into place without your OK and a backup. The steps are in HOW-TO-APPLY.txt, and you take them.
  • The backup. Make it yourself before anything changes, and confirm it exists.
  • Your MO2 version. Moving from 2.5.2 to a 2.5.3 beta is your choice.
  • Sharing. You decide whether a report or log leaves your PC.
