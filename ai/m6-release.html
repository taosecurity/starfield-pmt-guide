Part 2: For modders

Release a mod with an agent

Do this by hand

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

Your agent builds the zip, runs the release check, confirms it is the build you tested, drafts the README and sets up patch-day upkeep. It never uploads. You read the findings, write or approve the release text, and upload to Nexus Mods or Creations yourself.

On this page
  • What to ask
  • What the agent runs
  • What you check
  • What stays your decision
  • For CK and xEdit authors
  • For code builders

What to ask

Ask your agent
Build the release zip for MyMod, run the release check with the creations profile, and explain every PROBLEM, REVIEW and WARNING line.
Ask your agent
Check that the zip I'm about to release is the build I tested.
Ask your agent
Draft the README for MyMod, including how to turn on Papyrus logging and credits for the authors whose work I used. I'll edit it.

What the agent runs

The starfield-agent skill release-check covers this task, and it is meant for the step before an upload to Nexus Mods or Bethesda Creations. The user uploads. Other agents follow sf-mod-check's, sf-mod-build's and sf-patch-day's AGENTS.md. The commands match the manual page.

Command Prompt
sf-mod-build build
Command Prompt
sf-mod-build check --require-check
Command Prompt
sf-mod-check release MyMod-1.0.0.zip --profile basic
Command Prompt
sf-mod-check release MyMod-1.0.0.zip --profile creations
Command Prompt
sf-test-plan check-build MyMod.testplan.md --built MyMod-1.0.0.zip --tested MyMod-0.9.0.zip

For a mod built for Creations with "xbox": true, the Creations check runs on the creations-out folder:

Command Prompt
sf-mod-check release creations-out --profile creations

For patch-day upkeep, the agent makes sure sf-pex-tools 0.1.0 sits in a folder named sf-pex-tools next to sf-patch-day (or adds --pex-tools <folder>). Without it, a mod that only adds its own records gets a mods file with nothing to watch, and snapshot exits 3.

Command Prompt
.\sf-patch-day.cmd drift init MyMod.esm -o mods.json
Command Prompt
.\sf-patch-day.cmd drift snapshot --mods mods.json -o baseline.json
Command Prompt
.\sf-patch-day.cmd drift check --mods mods.json --baseline baseline.json

What you check

  • The release lines and the exit code. Exit 0 is OK. PROBLEM must be zero. Ask the agent to explain each REVIEW and WARNING, and don't accept a finding you don't understand.
  • The gap check. sf-mod-build build prints BuildKit's gap check: result (0.4.2 and later). The agent should quote it and fix every ERROR, and say so if it reads NOT RUN.
  • The Creations folder. With "xbox": true, the Creations check belongs on creations-out. The PC zip has no Xbox archive. Without "xbox": true there is no creations-out folder, and the check exits 2 (CANNOT CHECK), which means nothing was checked.
  • check-build. Exit 0 means the zip has the same plugins and scripts as the one you tested.
  • One plugin per zip. The agent should split a second plugin into its own zip, and never use an "Optional" folder.
  • The README. Check that the logging section, the credits and the permissions are true. The agent can't know what an author told you.
  • Drift. After a game update, the agent must run drift check, not snapshot --force. Look at any ACTION line yourself. An exit 3 with "masters" is empty means the mods file has nothing to watch, not that the mod is fine.

What stays your decision

  • Whether the mod is ready, and which findings you accept.
  • The release text, the screenshots, the page and the version number.
  • Permission for any work you build on, and credit to its authors.
  • The upload to Nexus Mods and to Creations. The agent never uploads, and the Creation Kit does the Creations upload.
  • Whether to rebuild after drift check says ACTION.

For CK and xEdit authors

The agent can run release on your zip, draft the README and track patch-day drift. It can't open the CK or upload for you. You make the zip and the upload.

For code builders

The agent can run sf-mod-build build with the check required, split plugins into projects, and keep the Mutagen and BuildKit pins. It must never compile with -release, and it must never upload.

Read the guardrails before you let an agent act on your files.
