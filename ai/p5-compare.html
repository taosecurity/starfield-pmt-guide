Part 2: For players

Agents and the other modding tools

Do this by hand

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

An agent can fully drive only PMT, whose tools run from a command line (all but one window and one library) and reports back in text. Vortex, MO2 and LOOT each have a narrow command line, but none of them reports what it found in a form an agent can check (MO2's exit code only says whether the launch worked). xEdit's xDump prints a check report, though its exit code is always 0, and the Creations menu has no command line. You keep using those apps yourself, and the agent checks the result with PMT. The full comparison chart is on the manual page.

What to ask

Ask your agent
I just sorted my load order with LOOT. Check it with sf-load-order and explain the Top 10 findings.
Ask your agent
I reordered my Creations in the in-game menu. Check the game's Plugins.txt and tell me what to move, but don't change anything.

Which tools an agent can drive

An agent works by running commands and reading files. It can drive a tool only when that tool has a command line and prints its results as text.

ToolCan an agent drive it?Docs for agents
PMTYes. Every tool has a command line, except StarfieldVoiceTool's window (its starfieldvt-export command works) and BuildKit, which is a library the agent writes code for.Yes. An AGENTS.md in every tool, plus the starfield-agent plugin for Claude Code.
LOOTPartly. --game=Starfield --auto-sort sorts, applies the order and quits, with no report. It changes your load order with no preview.No. The LOOT and libloot repositories have no AGENTS.md or similar file.
VortexPartly. --install-archive <path> starts installing a zip in Vortex, --get <path> prints a value from Vortex's stored state (profiles and mods included), and --set, --del and --restore change it. It has no command to deploy, sort or report a result.Partly. Its repository has an AGENTS.md, but it is for people who change Vortex's code.
MO2Partly. ModOrganizer.exe run -e "<configured executable name>" starts a program you set up in MO2. It returns 0 or 1, never the program's own exit code.No. None of the ten MO2 repositories we listed on GitHub on 2026-11-24 has an AGENTS.md or similar file.
xEditPartly. xDump.exe reads and checks plugins from the command line. Its exit code is always 0, so a run counts only when its error output ends with "All Done.".No. The xEdit repository has no AGENTS.md or similar file.
Creations menuNo. It is inside the game.No.

We read the command lines in each tool's source or documentation on 2026-11-24: LOOT's command line parameters, Vortex's src/main/src/cli.ts (lines 204 to 263 at v2.11.0) and MO2's modorganizer/src/commandline.cpp (lines 698 to 790 in the 2.5.3 beta 12 source). We have run xDump on 4.1.5r hotfix 2 and 4.1.5s, and we haven't run the others. For Vortex, MO2 and LOOT, the agent has to read what the program wrote, such as Plugins.txt or a PMT report, to learn whether the run worked.

The full chart, with sources for every cell, is on How PMT compares with other tools.

What the agent runs

The agent runs the same PMT commands as the manual page, after you have used the other tools yourself. There is no dedicated starfield-agent skill for this page. Other agents follow each tool's AGENTS.md.

Command Prompt
.\sf-load-order.cmd
Command Prompt
sf-mod-check triage SomeMod-1.2.0.zip

For a Vortex setup, the agent asks you to deploy in Vortex first, then runs sf-load-order on the Plugins.txt that Vortex writes. With our Vortex Modlist Backup fork (no release yet), it can use --vortex-profile <name> instead. For MO2, it uses --mo2 <instance> --profile <name>.

Where an agent adds nothing

  • Installing and removing mods. You do this in Vortex, MO2 or the Creations menu, and you answer their install choices yourself. An agent can only start a Vortex install (--install-archive).
  • Applying a sorted order. LOOT sorts and applies. sf-load-order sort also builds an order, but it only writes files and steps. The agent can run it and explain it, and you apply the order yourself.
  • Editing records. Fixes to a plugin happen in xEdit or the Creation Kit, by you. The agent can point you to the records the report lists.
  • Ordering Creations. You drag them in the in-game menu. The agent can tell you the order sf-load-order suggests.

What you check

  • The RESULT: line and the exit code of each PMT command. Ask the agent to quote them.
  • That the agent's summary matches report.txt, especially the Top 10.
  • That the agent hasn't claimed a feature for Vortex, MO2, LOOT, xEdit or the Creations menu that isn't on the manual page's chart or the tool's own page.

MO2 2.5.2 and the 2.5.3 betas

MO2 2.5.2 (2024-08-04) is the last stable release. The 2.5.3 betas, shared on the MO2 Discord (beta 12 was released on 2026-05-23), carry newer Starfield support from the upstream modorganizer-game_bethesda repository. The Discord isn't a public source, so we cite the repository. What changed for Starfield, in short:

  • MO2 pins twelve of Bethesda's own plugins in the betas, up from eight in 2.5.2. The new ones include Shattered Space and Terran Armada.
  • The betas handle blueprint plugins on their own and warn about broken ones. Version 2.5.2 treats them as ordinary plugins.
  • The betas no longer write their own Starfield.ccc. Version 2.5.2 did.
  • The betas read the plugin list of current saves (save version 153). Version 2.5.2 likely misreads them. This comes from the source code and wasn't tried in a run.
  • The sorting library inside MO2 goes from LOOT 0.23.0 (libloot) to 0.29.4.
  • The betas show each Creation once, under its store title.

The manual page has the details. An agent should still ask which MO2 version you use before it explains a load-order warning, because the answer differs.

What stays your decision

  • Which manager, sorter and editor you use.
  • Applying any suggested order. The agent never copies suggested files into place without your OK and a backup.
  • Every change you make in Vortex, MO2, xEdit or the Creations menu.

Read the guardrails before you let an agent act on your files.
