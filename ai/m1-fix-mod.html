Part 2: For modders

Fix what an evaluation found with an agent

Do this by hand

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

Your agent runs sf-mod-check, explains each finding, and for a mod you build from code, changes the builder and re-runs the same check until it is clean. It can't edit a plugin in xEdit or the Creation Kit for you. If the mod is someone else's, the agent asks about permission before it does anything.

On this page
  • What to ask
  • What the agent runs
  • What you check
  • What stays your decision
  • For CK and xEdit authors
  • For code builders

What to ask

Ask your agent
Run sf-mod-check check on MyMod.esm and explain each finding in plain words. Point to the record each one names.
Ask your agent
Fix the problems in my builder, rebuild, and run the same check again. Tell me the RESULT line each time.
Ask your agent
This mod is by another author. Before you change anything, tell me what permission I need and what to credit.

What the agent runs

The skills evaluate-mod, rebuild-mod and build-mod of starfield-agent cover this task. rebuild-mod handles another author's mod and asks about permission first. Other agents follow sf-mod-check's AGENTS.md and sf-mod-build's AGENTS.md. The commands match the manual page.

Command Prompt
sf-mod-check check MyMod.esm
Command Prompt
sf-mod-check release MyMod-1.0.0.zip
Command Prompt
sf-mod-check triage SomeMod-1.2.0.zip

Since sf-mod-check 0.17.0 (released 2026-11-24), triage lists every changed field of each official record the mod overrides. Each record shows at most 200 rows, plus up to 200 more for the two translation kinds, and each value is cut at 2,000 characters. The whole report holds at most 10,000 rows, with real changes first. Each cut says how much it left out. The agent should treat the rows "same entries, other order" and "same English text, translations dropped" as often harmless and start with the other rows.

Command Prompt
sf-mod-check gap MyMod.esm
Command Prompt
sf-mod-check diff SomeMod-1.1.0.zip SomeMod-1.2.0.zip
Command Prompt
sf-mod-build build

What you check

  • The RESULT line and the exit code. Don't accept "it's fixed" without them. Exit 0 means no errors for check and OK for release.
  • The same command each time. Ask the agent to rerun the exact command that found the problem, not a different one that passes.
  • The finding level. ERROR and PROBLEM must be fixed. WARNING and REVIEW are for you to judge.
  • Triage. The agent must call it "where to start reading", never a safety verdict, and must not report a bug to an author from triage alone.
  • What changed. For a code build, ask for the diff of the builder, so you see what the agent touched.

What stays your decision

  • Whether to fix someone else's mod at all, and whether the author has agreed. The agent asks, and you keep their reply.
  • Whether to share a fixed version, and how to credit the author.
  • Which findings you accept. The agent can suggest --accept, and you decide.
  • Any edit in xEdit or the Creation Kit, because an agent can't drive those windows. Cleaning ITMs, undeleting and renumbering are yours.

For CK and xEdit authors

The agent can read the findings, tell you which record to open and what is probably wrong, and run the check again after you save. It can't edit the plugin, so you make the fix.

For code builders

The agent can change your builder, rebuild with sf-mod-build build and run check and gap on the result. Review its changes before you keep them, and tell it to match how the game's own records do it.

Read the guardrails before you let an agent act on your files.
