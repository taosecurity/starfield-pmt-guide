Part 2: AI-assisted

Set up an AI agent

Do this by hand

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

This page sets up an AI coding agent to run the PMT tools for you. Claude Code can add the starfield-agent plugin, which brings twelve skills, two safety guards and a Papyrus lookup server. Other agents follow each tool's AGENTS.md file instead.

What you need

  • The tools. Install the PMT tools you want first, as described in Getting started. The agent runs them, so they must work by hand.
  • An AI coding agent. Claude Code is the one starfield-agent was built for. It needs version 2.1.330 or newer.
  • Python 3.9 or newer on your PATH, as python. The plugin's guards are Python scripts. Without Python, the guards refuse every call they cover, on purpose.
  • Git. The game-code guard and the skills that commit need it.
  • Optional: the .NET 9 SDK or later, for sf-mod-build and BuildKit. With it, the agent can also install sf-mod-check from nuget.org (since version 0.18.0) with dotnet tool install --global sf-mod-check, and update it later with dotnet tool update --global sf-mod-check. Ask it to show you the command before it runs it.
Warning

The tools are free, but an AI agent is a paid service. Its service sees what the agent reads, including file names and log text. Don't let it read what you wouldn't share.

Install starfield-agent in Claude Code

starfield-agent is a Claude Code plugin and its own plugin marketplace. It adds twelve skills, two guard hooks and a Papyrus lookup server. There is nothing to download: its GitHub release (0.2.1) has no files, because Claude Code reads the plugin straight from the GitHub repository. In Claude Code, the two commands are /plugin marketplace add taosecurity/starfield-agent and /plugin install starfield-agent@starfield-agent. The plugin's README gives the same two commands for a terminal, with claude plugin in front. This guide's command run on 2026-11-24 did not try the install, so if a command isn't accepted, use the /plugin form inside Claude Code:

Command Prompt
claude plugin marketplace add taosecurity/starfield-agent
Command Prompt
claude plugin install starfield-agent@starfield-agent

Restart Claude Code afterward. If you used the older plugin called starfield-modding, uninstall it first and set your plugin options again.

Run the first-use setup

In Claude Code, type this to let the plugin find your game, saves and mod manager, save its settings and list the tools it found:

Ask your agent
/starfield-agent:setup

You can also ask in words:

Ask your agent
Set up the Starfield tools. Find my game folder, my saves and my mod manager, and tell me which tools you found and which are missing.

The settings can come from environment variables (SFMOD_GAME_DIR, SFMOD_SAVES_DIR, SFMOD_EXTRA_GUARDED and SF_PAPYRUS_REF), from the plugin options, from a project file at .claude/starfield-agent.json, or from a user file in %APPDATA%\starfield-agent\. To change the plugin options, run:

Command Prompt
claude plugin configure starfield-agent@starfield-agent

If you use Mod Organizer 2 or Vortex, set mod_manager (kind mo2 or vortex, and its path). Add Vortex's staging folder or MO2's overwrite folder to extra_guarded. With Vortex you still drop zips onto Vortex yourself.

The two guards

starfield-agent adds two hooks that run before the agent's tool calls. Don't turn them off to finish a task. If a guard refuses something it should allow, tell the agent to stop and open an issue on the starfield-agent repository.

  • The game guard refuses changes to the game's Data folder, your saves folder, Plugins.txt and ContentCatalog.txt. Read-only modes of the tools still work.
  • The game-code guard refuses git add, git commit, git push, gh release create, gh release upload and gh gist create when they would carry official plugins or archives, game or Creation Kit executables, official script sources, saves, or Ghidra and IDA databases. It asks when a file looks like decompiler output.

A guard that refuses ends with a starfield-agent guard: reason on stderr. The guards read command text, so a path built at run time (in a variable or a script file) isn't seen by the shell guard.

Other agents

The plugin, skills and hooks run only in Claude Code. Every PMT tool also ships an AGENTS.md, which any agent that can run commands can follow. It lists the commands, the exit codes and what the agent must not do.

For Papyrus lookups, sf-papyrus-ref includes a read-only MCP server. In Claude Code the plugin sets it up for you. Other MCP clients start the same command:

Command Prompt
python -I sf_papyrus_ref.py mcp --quiet

What the agent can do

These are the twelve skills. Claude Code runs them as /starfield-agent:<skill> or loads one when your request matches.

SkillWhat it does
setupFinds your game, saves and mod manager, saves settings and lists tools.
new-modStarts a new mod.
build-modCompiles Papyrus (never in release mode), writes the plugin, packs and checks.
rebuild-modFixes another author's mod. It asks for permission first and gives credit.
evaluate-modSays what a mod or an update does.
test-planMakes a test plan for a new character, with log checks.
log-reviewReads logs after a test and drafts a result for each mod.
release-checkChecks a mod before Nexus Mods or Creations. You upload.
patch-dayAfter a game update, checks SFSE plugins, mods and load order.
logging-rulesApplies the logging rules for scripts.
game-code-rulesApplies the rules about never sharing game code.
wrap-upUpdates the project notes and commits.
Note

PMT runs on a PC. The agent runs on your PC, with your permission. Console-only players can still use it to check a mod on a PC.

What stays your decision

You decide whether to install a mod, whether to apply a load order, whether you have permission to change another author's mod, and whether to upload or share anything. The agent never uploads. Read the guardrails before your first real task.

Prove it works

Check that the plugin is installed and enabled:

Command Prompt
claude plugin list

It should show starfield-agent@starfield-agent enabled. For more detail:

Command Prompt
claude plugin details starfield-agent@starfield-agent

You should see twelve skills, one PreToolUse hook entry and one MCP server, papyrus-ref. Then run the plugin's own self-test from the plugin folder. Claude Code keeps an installed plugin in %USERPROFILE%\.claude\plugins\cache\<marketplace>\<plugin>\<version>, so for this plugin look for cache\starfield-agent\starfield-agent\0.2.1. The file %USERPROFILE%\.claude\plugins\installed_plugins.json names the exact folder as installPath. Open a Command Prompt there.

Command Prompt
python -I selftest.py

It should end with RESULT: OK. Without Claude Code, add --no-claude.

To check the Papyrus server, run this in the plugin folder:

Command Prompt
python -I mcp/papyrus_ref_launcher.py --find

Last, ask the agent to prove a tool for you:

Ask your agent
Run sf-load-order's version command and tell me what it printed.
