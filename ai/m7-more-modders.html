Part 2: For modders

More tools for modders, with an agent

Do this by hand

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

The sf-papyrus-ref MCP server lets an agent look up a Papyrus name instead of inventing one. Your agent can also compare compiled scripts, look for unused records and export voice lines. It must never share the game's script text or extracted files.

On this page
  • What to ask
  • What the agent runs
  • What you check
  • What stays your decision
  • For CK and xEdit authors
  • For code builders

What to ask

Ask your agent
Before you write any Papyrus call, look it up with sf-papyrus-ref, and tell me if a name isn't found.
Ask your agent
I recompiled my scripts. Compare the old and new compiled scripts and tell me whether anything really changed.
Ask your agent
Scan MyMod.esm for records I added but nothing uses, and explain what Orphaned and Unreferenced mean.

What the agent runs

The sf-papyrus-ref MCP server, which starfield-agent includes as the papyrus-ref server, gives an agent four tools: papyrus_lookup, papyrus_script, papyrus_list_flag and papyrus_check. The starfield-agent skill game-code-rules sets what an agent may do with the game's scripts. Other agents follow each tool's AGENTS.md, and any agent that supports MCP can start the same command. The commands match the manual page.

Command Prompt
python -I sf_papyrus_ref.py mcp --quiet
Command Prompt
sf-papyrus-ref lookup Debug.Notification --no-local
Command Prompt
sf-papyrus-ref check Scripts --creations
Command Prompt
python -I pex_compare.py compare <A> <B>
Command Prompt
python -I ba2_extract.py list <archive>
Command Prompt
sf-cut-check scan --plugin MyMod.esm
Command Prompt
sf-cut-check why <FormID:Plugin.esm or EditorID>
Command Prompt
starfieldvt-export voices --out <folder> --plugin Starfield.esm --search "text" --list

For a scripted voice export, the agent uses starfieldvt-export, not the window, and runs --list first.

What you check

  • found: false. If a lookup says a name isn't found, the agent must not use it unless it can read the script that defines it.
  • check exit codes. Exit 0 means no errors (warnings are allowed), and exit 1 means at least one error. With --creations, Debug.Trace, Debug.Notification and Debug.MessageBox are warnings and other DebugOnly calls are errors, so the agent doesn't need --allow for the usual debug-switch pattern.
  • [name only] findings. Chained calls are matched by name only, so they are less certain.
  • The compiler. sf-papyrus-ref isn't a compiler. The Papyrus compiler is the final judge, so look at the compile result.
  • Orphaned and Unreferenced. Treat them as "nothing in the plugins uses it". Scripts aren't read, so a record a script fetches can look unused.
  • Exit codes and the output words (same, DIFFERENT, ONLY IN, UNREADABLE) from sf-pex-tools.

What stays your decision

  • Whether a function is right for your mod. The lookup says it exists, not that it fits.
  • Whether to delete a record sf-cut-check flags.
  • Which voice lines to export, and whether you may share them. Exported audio is the game's or the mod's content.
  • Sharing anything at all from the game's scripts or archives. The answer is no.

For CK and xEdit authors

The agent can look names up while you write scripts in the CK, run check on your scripts, and compare compiled scripts. It can't write records in the CK for you.

For code builders

The agent can write against BuildKit, including its quest helpers (since version 0.6.0, see Build a quest mod with an agent), and look up every Papyrus name first. Ask it to run sf-papyrus-ref check and sf-cut-check scan --plugin on each build, and to keep the Mutagen 0.54.4 pin.

Warning

Never let an agent share the sf-papyrus-ref html site, its local cache or extracted game files, because they hold Bethesda's content. Don't put them in a repository, a release or a message.

Read the guardrails before you let an agent act on your files.
