Part 1: For players

Evaluate a mod before you install it

Do this with an agent

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

Three commands tell you where to start reading a download (sf-mod-check triage), which files and records it shares with the mods you already have (sf-load-order candidate), and which records it changes once it is installed (sf-mod-check conflict). None of them gives a safe or unsafe verdict. Reading the mod page, its requirements and its permissions stays your job.

What you need

  • sf-mod-check 0.16.2 and sf-load-order 0.3.0, installed as in Getting started.
  • The download. Keep the zip, 7z or rar file that the mod page gave you. SomeMod-1.2.0.zip stands in for it below. To use candidate on a .7z or .rar, install 7-Zip.
  • sf-mod-check on your PATH (0.8.0 or newer), or its path given with --sf-mod-check. candidate needs it for the record check.
  • Your setup. Steam or Game Pass, with Vortex, Mod Organizer 2 (MO2), no manager, or only the Creations menu. The commands below don't change by setup, except that candidate and the load order check take the same load order options as P1.
  • A way back. Install through Vortex or MO2 so you can disable or remove the mod again. Back up your load order first.

Steps

1. Read the mod page

Before you run any tool, read the mod page, its requirements, its permissions and the recent comments. PMT can't do this for you, and it can't judge quality.

2. Triage the download

triage unpacks the download in a temporary folder and lists what it contains. Every finding is a NOTE or a LOOK. Treat it as "where to start reading", never as a verdict.

Command Prompt
sf-mod-check triage SomeMod-1.2.0.zip

It takes zip, 7z and rar files, a folder, or a single plugin. It writes <name>-triage.html (to read), <name>-triage.txt and <name>-triage.json (for scripts), named after the download, for example SomeMod-triage.html. They go next to the download. Add --out <folder> to choose another folder, which you must do when the download sits inside the game's install folder.

Since sf-mod-check 0.17.0 (released 2026-11-25), triage shows every changed field of a record the mod overrides, one row per changed value, with the whole value before and after. Two row names mean the difference is often harmless: "same entries, other order" is a list that holds the same entries in a new order, and "same English text, translations dropped" is a text whose English is unchanged but whose other-language versions the mod doesn't carry. Read those rows last.

To see what one plugin changes before you install it, unzip the download into a folder of your own and use find --plugin. With no record named, it lists every record the plugin holds and ends with a summary by type. It prints the first 100 records. Add --max 0 to list them all, or --type <SIG> to keep one record type. It looks for each master in the plugin's own folder, then in each --masters-dir, then in the game's Data folder.

Command Prompt
sf-mod-check find --plugin "<folder>\SomeMod.esm" --masters-dir "<folder of a required mod>"

3. See what it shares with your mods

candidate compares the download's scripts, loose files and archives with the mods you have installed. It also compares records: for each installed mod whose records the download also changes, it reports how many. It reads .zip, .7z and .rar downloads.

Command Prompt
.\sf-load-order.cmd candidate SomeMod-1.2.0.zip

Add the load order options for your manager, the same ones P1 uses. For example, with Vortex, deploy first and add the fork's --vortex-profile only if you use it (see P1):

Command Prompt
.\sf-load-order.cmd candidate SomeMod-1.2.0.zip --vortex-profile "<profile name>"

The default depth, medium, runs sf-mod-check conflict on your load order with the download added, so it takes as long as one conflict run, about 2 minutes on a 150-plugin load order. --depth light compares file names only and takes seconds, and its report has a note that the record check didn't run. For a longer check that also runs sf-mod-check's plugin checks on the download's plugins, add --depth heavy.

For a .7z or .rar, give its name the same way:

Command Prompt
.\sf-load-order.cmd candidate SomeMod-1.2.0.7z

Under MO2, the record check sees MO2's mods only when sf-load-order is started from MO2. Run from a command prompt, candidate gives one caution that the records weren't checked. After you install the mod, sf-mod-check conflict --mo2 "<instance folder>" covers the records.

4. Install it, then check the records

Install the mod with your manager. Then run the normal load order check and the conflict report. The conflict report tells you which records the new mod changes that another mod also changes.

Command Prompt
.\sf-load-order.cmd
Command Prompt
sf-mod-check conflict

Open report.html from the conflict run. P3 explains it.

5. Check an update before you replace the old one

When a new version arrives, compare it with the one you have. diff lists what changed in records, cells, leveled lists, loose files, archives and scripts.

Command Prompt
sf-mod-check diff SomeMod-1.1.0.zip SomeMod-1.2.0.zip

6. Check a Creation

A Creation can be checked only after the game installs it. Install it from the Creations menu, run sf-mod-check check on its plugin and the load order check, and remove it from the menu if you don't like what you see.

Command Prompt
sf-mod-check check OtherMod.esm

Example

The mechanics tutorial in this guide (M3) makes a small zip, PMTTutorialSecondWind-0.1.0.zip, that you can use to try these commands.

Command Prompt
sf-mod-check triage PMTTutorialSecondWind-0.1.0.zip
Command Prompt
.\sf-load-order.cmd candidate PMTTutorialSecondWind-0.1.0.zip

A download from Nexus Mods works the same way. Save the file, leave it zipped, and give its name to the commands.

Reading the results

  • Triage. NOTE lines say what the mod contains. LOOK lines say where to read first. Neither one says the mod is good or bad. Triage can't see what a DLL or script does when the game runs.
  • Candidate. It lists scripts, loose files and archive contents that the download shares with installed mods. A shared script is a problem, and a file with different content is a problem or a caution. For records, one caution per installed mod says how many records the download also changes, how many of them have fields a conflict patch can forward (Forwardable) or fields both mods changed (Choice), and who wins them, with up to five examples. A note means the shared records differ in nothing that matters. If a download's master isn't installed, a caution names it. The run writes report.txt, report.html and report.json to sf-load-order-report (or the --out folder) and ends with RESULT: n problem(s), n caution(s), n note(s) (report: ...).
  • Conflict report. report.html, report.md and conflicts.json list records that two or more mods change. The later one in your load order wins.
  • Diff exit codes. 0 means no differences. 1 means differences were found. 2 means a bad input.
  • Triage exit codes. 0 means the report was written. 2 means it could not run.
  • Check exit codes. 0 means no errors. 1 means errors. 2 means the tool could not check.

When PMT isn't enough

By design

Triage is never a safety verdict. It can't see what a DLL or script does when the game runs. Reading the mod page, judging quality, and deciding whether to trust an author are yours. Never report a bug to an author from triage alone.

Note

A Creation can be checked only after the game installs it, because the game downloads Creations itself.

Note

PMT runs on a PC. If you play on a console, you can check a mod on a PC first, but you can't install PC files on your console.
