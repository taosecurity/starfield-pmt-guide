Part 1: For players

How PMT compares with other tools

Do this with an agent

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

This page compares PMT with Vortex, Mod Organizer 2, LOOT, xEdit and the in-game Creations menu, and says when to use PMT together with each one. PMT checks and reports, while those tools install, sort, edit and order your mods, so most players use PMT alongside them rather than instead of them. Every claim about another tool links to its source, checked on 2026-11-24.

The short answer

PMT doesn't replace the tools you already use. Vortex and Mod Organizer 2 (MO2) install and remove mods. LOOT sorts a load order. xEdit edits records. The in-game Creations menu installs and orders Creations. PMT checks what those tools produced, explains problems in plain words, checks saves and logs, and builds mods from code. It never installs, sorts from scratch, edits another author's plugin or uploads.

Note

Starfield reads Plugins.txt itself when it starts, and the game rewrites that file when it launches and when you move a Creation in the Creations menu. See Starfield Load Order Facts for the tests behind this. Some older xEdit documentation says the game doesn't read Plugins.txt. That is out of date.

What each tool does best

Vortex

Vortex is the Nexus Mods mod manager. It installs, enables and removes mods, and it deploys them into the real Data folder, which is why PMT tools work on a Vortex setup as they are. Its license is GPL-3.0 (repository). Its Starfield support lives in a game extension, and the old repository for that extension was archived on 2026-05-20 (vortex-games). We could not load Vortex's own pages on 2026-11-24, so this page doesn't say where the Starfield extension lives now or how far Vortex sorts, checks or reports conflicts for Starfield. See the Vortex documentation for those.

Mod Organizer 2

MO2 keeps every mod in its own folder and shows the game a virtual Data folder, so your real Data folder stays clean. MO2 also gives the game its own copy of Plugins.txt, unless StarfieldCustom.ini has sTestFile lines, which turn MO2's plugin management off (Starfield Load Order Facts). Version 2.5.2 added Starfield Creation support, medium plugin support, save parsing for saves up to version 139 (it lists a save's missing plugins), Starfield archive packing, and LOOT sorting turned on by default through libloot 0.23.0 (2.5.2 release notes). MO2 2.5.2 sorts with libloot 0.23.0, which is older than LOOT 0.24.0's blueprint master support (LOOT changelog), so its built-in sorting may not know the newer Starfield rules, and running LOOT itself avoids that. The 2.5.3 betas build against libloot 0.29.4 and the v0.29 masterlist, and add their own blueprint plugin handling. That comes from the source code, and we haven't tried it in a run.

MO2 2.5.2 and the 2.5.3 betas

MO2 2.5.2 (2024-08-04) is the last stable release. Newer builds, the 2.5.3 betas, are shared on the MO2 Discord. Beta 12 was released on 2026-05-23. The Discord isn't a public source, so the points below come from the upstream source code in the modorganizer-game_bethesda repository (where the Starfield support now lives), the modorganizer repository and the MO2 vcpkg registry. We read the beta 12 source on 2026-11-24 and did not run it, so we haven't tested what the game does with the differences.

What changed for Starfield between 2.5.2 and the betas:

  • Pinned official plugins, 8 to 12. MO2 pins Bethesda's own plugins at the top of the list and keeps them out of its plugins.txt. Version 2.5.2 pins eight. The betas pin twelve, including Shattered Space and Terran Armada, which 2.5.2 treats as ordinary plugins.
  • Blueprint plugins. Version 2.5.2 treats a BlueprintShips- file like any other plugin. The betas keep blueprint plugins in their own block after every other plugin, leave them out of plugins.txt, and warn about an invalid or unpaired blueprint file.
  • Starfield.ccc. Version 2.5.2 wrote its own Starfield.ccc and showed it to the game and to every program it started. The betas drop that and only read a Starfield.ccc that already exists.
  • Save version 153. Version 2.5.2 reads the plugin list of saves up to version 139 and likely misreads current saves (version 153). The betas read versions 140 and later. This comes from the source code and wasn't tried in a run.
  • LOOT 0.23.0 to 0.29.4. The sorting library inside MO2 (libloot) is 0.23.0 in 2.5.2 and 0.29.4 in the beta 12 source. A beta sort also shows the new order first and changes your load order only when you press Apply.
  • Creations shown by title. Version 2.5.2 listed each Creation plugin as its own entry. The betas show one entry per Creation, under its store title.

Two things stay the same in both versions. If StarfieldCustom.ini has sTestFile lines, MO2 maps nothing and turns its plugin management off. MO2's source code also has a command line that starts a configured program (ModOrganizer.exe run <executable>). We haven't tried it.

If you use 2.5.2, check after you change your plugins that Shattered Space and Terran Armada are still ticked in MO2's plugin list. If you can get a beta or a later release, prefer it for Starfield.

LOOT

LOOT sorts a load order from its masterlist and your own userlist rules, checks for errors such as missing masters, and shows messages about plugins (loot.github.io). Its Starfield support has grown since 2023: medium plugins and sorting in 0.23.0, blueprint masters in 0.24.0, and warnings for BlueprintShips- and blueprint master mistakes in 0.29.1 (changelog). The Starfield masterlist is public (loot/starfield). LOOT doesn't show record conflicts or build patches.

xEdit

xEdit (its Starfield mode is SF1Edit) is the standard tool for looking at and changing records by hand. It shows which plugin wins each record, cleans plugins, and can build patches by hand or by script (xEdit docs). Its license is MPL-2.0 (repository). The 4.1.5 docs say SF1Edit can't save plugins with the ESL or Overlay flags. We haven't checked whether that is still true in later builds.

The Creations menu

The Creations menu is built into the game. It installs Creations and lets you reorder them, with full masters first, then light masters, then other plugins, and it can block saving when two files share a name (Bethesda support: load order). You can restore an order only if you saved it to the Load Order Archive earlier, which is tied to your Bethesda.net account (Bethesda support: Load Order Archive). Creations are ordinary plugins in the same Data folder and the same Plugins.txt as your other mods (Starfield Load Order Facts). It is the only one of these tools on consoles.

PMT

PMT's strength is checking and explaining. It tells you what is wrong in a load order, a plugin, a release zip, a save or a log, in plain words, with a RESULT: line and an exit code. It also builds mods from code. Every tool ships an AGENTS.md, so an AI agent can run it the way its author intended (see Agents and the other modding tools).

When to use PMT with them

  • LOOT, then sf-load-order. Let LOOT sort, then run .\sf-load-order.cmd to check the result. Give it LOOT's masterlist with --loot-masterlist so its suggestions follow the same rules. See Check and improve a load order.
  • Vortex or MO2, then PMT. Install and remove mods with your manager, then check with PMT. For Vortex, deploy and run sf-load-order on the Plugins.txt that Vortex writes. With our Vortex Modlist Backup fork (no release yet), use --vortex-profile <name> instead. For MO2, use --mo2 <instance> --profile <name>, on sf-load-order and also on sf-mod-check conflict, patch and find.
  • PMT, then xEdit. When sf-mod-check's conflict report lists records it can't patch, such as quest and dialogue records, fix those in xEdit. Any fix to a plugin is an xEdit or Creation Kit job. See Find conflicts and build a patch.
  • The Creations menu, then sf-load-order. Order your Creations in the menu, then run .\sf-load-order.cmd with no options to check the game's Plugins.txt. If it suggests changes, make them in the menu.
  • Before you install anything. Run sf-mod-check triage on the download. None of the other tools looks inside a mod before it is installed. See Evaluate a mod before you install it.

Note

When the Creations menu and a mod manager both reorder your plugins, the last tool to write Plugins.txt wins (Starfield Load Order Facts). Pick one place to set the order, and check it with sf-load-order after any change.

When PMT isn't enough

By design

PMT doesn't sort a load order from scratch, install mods or edit records. Use LOOT to sort, Vortex, MO2 or the Creations menu to install and order, and xEdit or the Creation Kit to change records. PMT checks the result.

By design

PMT runs on a PC. Console players can use only the Creations menu. To check a Creation, install it on a PC and run PMT there.
