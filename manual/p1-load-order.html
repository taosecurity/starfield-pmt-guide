Part 1: For players

Check and improve a load order

Do this with an agent

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

sf-load-order reads your load order and tells you in plain words what is wrong, such as a patch that loads before its master, and suggests a better order. It only reads and reports. Sorting from scratch is LOOT's job, and applying the suggested order is your step.

On this page
  • What you need
  • Steps
  • Reading the results
  • When PMT isn't enough
  1. 1Close the game and finish any changes in your mod manager.
  2. 2Run the check for your setup.
  3. 3Read report.txt, starting with the Top 10.
  4. 4Back up, then apply the suggested order yourself.

What you need

  • sf-load-order 0.2.3, installed as in Getting started. It needs Python 3.9 or newer.
  • Optional: sf-mod-check 0.8.0 or newer, if you also want record conflicts in the report. Put it on your PATH, or point to it with --sf-mod-check EXE. P3 explains record conflicts.
  • Your setup. The game reads a file called Plugins.txt to learn which plugins are active and in what order, and the game also rewrites that file. A manager and the game can therefore overwrite each other. Starfield Load Order Facts shows the tests behind this.
  • A backup. Copy your Plugins.txt, or your manager's profile, somewhere safe before you apply anything.
  • A quiet game. Don't run the check while the game or your mod manager is changing the load order.
  • A PC. PMT reads PC files only, so it can't check a console load order.
Warning

The log and the reports hold your folder names. Read them before you post them anywhere.

Steps

Pick the route that matches how you play. Every route writes report.txt, report.html and report.json, plus a suggested plugins.txt and a HOW-TO-APPLY.txt with the steps. Reports go to a folder called sf-load-order-report unless you give --out.

If you use no manager (Plugins.txt)

With no options, sf-load-order reads the game's own Plugins.txt in %LOCALAPPDATA%\Starfield. Steam and Game Pass share the same file, and the tool finds your Data folder by itself. If it can't, add --data with your Data folder.

Command Prompt
.\sf-load-order.cmd

To check a copy of the file instead of the live one:

Command Prompt
.\sf-load-order.cmd --plugins-txt "<path to a Plugins.txt copy>"

If you use Vortex

The default route needs no extension. Deploy your mods in Vortex, which writes the game's Plugins.txt, and then run sf-load-order on that file as in the no-manager route above.

Command Prompt
.\sf-load-order.cmd

The optional route is our fork of the Vortex Modlist Backup extension (github.com/taosecurity/Vortex-Modlist-Backup), which is a fork of Garethp's Vortex Modlist Backup. The fork has no release yet. Garethp's original backs up only the mod list, not the load order. In the fork, the toolbar button on the Mods page, "Back Up Modlist and Load Order (This Profile)", writes the load order file that --vortex-profile reads:

Command Prompt
.\sf-load-order.cmd --vortex-profile "<profile name>"

If you use MO2

Run .\sf-load-order.cmd --mo2 <instance> --profile <name> to read an MO2 profile. For Starfield, prefer the 2.5.3 beta (beta 12 was released 2026-05-23) or a later release over 2.5.2, the last stable release (2024-08-04), because the betas handle the official plugins, blueprint plugins and current saves better (what changed). If you stay on 2.5.2, check that Shattered Space and Terran Armada stay ticked in MO2's plugin list after you copy a suggested order in. MO2 2.5.2 treats them as ordinary plugins and can switch them off. If StarfieldCustom.ini has sTestFile lines, MO2 turns its plugin management off in every version, so remove them first (details). When your load order has official plugins that MO2 2.5.2 doesn't pin, such as Shattered Space and Terran Armada, the report has one caution and HOW-TO-APPLY.txt has one step that tells you to check they are still ticked.

Command Prompt
.\sf-load-order.cmd --mo2 "<instance folder>" --profile "<profile name>"

For MO2 the tool also writes loadorder.txt.

For record conflicts between MO2 mods, give sf-mod-check the same instance and profile. Its conflict, patch and find commands take --mo2 (0.16.0 and later) and read the profile the way MO2 builds its virtual Data folder. Without --mo2, they see only the plugins in the real Data folder.

Command Prompt
sf-mod-check conflict --mo2 "<instance folder>" --profile "<profile name>"

sf-load-order's own record section still sees MO2's mods only when sf-load-order itself is started from MO2 (add sf-load-order.cmd as an MO2 executable). Instead, give it the report you just made: .\sf-load-order.cmd --mo2 "<instance folder>" --profile "<profile name>" --conflicts conflicts.json, where conflicts.json is the file the conflict run wrote. sf-mod-check's MO2 support was tested on made-up MO2 folders, so the first time, check that the report's load-order line reads MO2 profile <name> (<folder>), <n> active entries, and read its load-order problems.

If you use only the Creations menu

Creations are ordinary plugins in the same Plugins.txt, so the default run reads them. The tool skips the official files, including Bethesda's free Creations, because they load in a fixed order.

Command Prompt
.\sf-load-order.cmd

Starfield itself writes Plugins.txt, at every start and whenever you change the order in Creations. HOW-TO-APPLY.txt has a part for players who use only the Creations menu, with two routes:

  • Copy the file. With the game closed, back up your Plugins.txt and copy the suggested plugins.txt over it. In the tool's own test, the game's start-up rewrite kept every plugin line in its place (Starfield Load Order Facts).
  • Use the menu. Open Creations, then Load Order, and move each Creation until the list matches the mod lines of plugins.txt.

Pick one place to manage the order, because a later change in Creations replaces what you copied. If you also use Vortex or MO2, the last tool to write Plugins.txt wins.

Choose how deep to look

--depth takes light, medium or heavy. Light skips record conflicts and takes seconds. Medium, the default, adds record conflicts through sf-mod-check conflict, which takes a few minutes on a big load order. Heavy also runs sf-mod-check check on every enabled mod plugin, for identical-to-master records and deleted references. That adds several seconds per plugin, so a heavy run took about 14 minutes on a 150-plugin load order in this guide's test (2026-11-24), and the screen shows nothing but the tool's name until it ends. Add --log <file> to watch its progress in the log.

Command Prompt
.\sf-load-order.cmd --depth heavy

Apply the suggestion yourself

Open HOW-TO-APPLY.txt in the report folder. Back up first, then follow its steps. The tool never copies anything into place for you.

Before you apply anything, read the report for one caution about StarfieldCustom.ini. sf-load-order 0.2.3 gives it when that file (in Documents\My Games\Starfield, or the MO2 profile's own copy when the profile uses local INI files) has sTestFile lines. The game and MO2 load the files those lines name and skip Plugins.txt, so the order in the report may not be what the game loads. Back up the INI, remove the lines, and run the check again.

Reading the results

The screen ends with one line in this form:

RESULT: n problem(s), n caution(s), n note(s)

A problem is something likely to break your game, such as a missing or late master. A caution is worth fixing. A note is only information. Open report.txt and read the Top 10 findings first. report.html shows the same report in a browser, and report.json is for other programs.

Exit codeMeaning
0The report was written, even if it found problems.
1You used --strict and at least one problem was found.
2The tool could not run. The line says RESULT: CANNOT CHECK.

Add --strict when you want a script to fail on any problem. The tool keeps your current order when a suggested change would save less than 10 points or 3%.

When PMT isn't enough

By design

sf-load-order doesn't sort a load order from scratch. Use LOOT for that. The tool can read LOOT's masterlist with --loot-masterlist. It also never edits Plugins.txt, Vortex or MO2, so applying the order is your step.

By design

A mod's ship change can't beat an official BlueprintShips- file. That is an engine rule, and no tool can change it.

Vortex and MO2 can also sort and apply an order. See how PMT compares for who does what.
