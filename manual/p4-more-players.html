Part 1: For players

Saves, bug reports and patch day

Do this with an agent

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

This page covers four jobs for players. You can check a save against your mods, collect logs for a good bug report, check your Starfield Script Extender plugins after a game update, and look up voice lines and game data. The tools only read and report, so keeping backups and reading files before you share them stay your job.

On this page
  • What you need
  • Steps
  • Example
  • Reading the results
  • When PMT isn't enough

What you need

  • The tools for the job you choose, installed as in Getting started: sf-save-health 0.7.4 and sf-save-reader 0.1.3 for saves, sf-log-collector 2.1.0 and papyrus-log-check 0.4.2 for bug reports, sf-patch-day 0.3.0 for patch day, and StarfieldVoiceTool 0.10.0 for voice lines.
  • Your setup. Steam saves are in Documents\My Games\Starfield\Saves. Game Pass saves live in an Xbox container, and you must export them to .sfs files first (see the limit note below). Vortex works as it is. Under Mod Organizer 2 (MO2), run the save tools from MO2 as an executable, or every mod looks missing.
  • Backups. Copy your saves to a safe folder before you test anything with them.

Steps

Part 1: Check a save

check compares one save with the mods installed now. Give it your Plugins.txt so it can also check the load order.

Command Prompt
sf-save-health check "<save.sfs>" --plugins "%LOCALAPPDATA%\Starfield\Plugins.txt"

To see what a mod did to a save, make two manual saves, one before and one after the change, then compare them. solo reports only what changed. It refuses an exit save, the same save twice, saves from two different characters, or an "after" save older than the "before" save, and then exits 3.

Command Prompt
sf-save-health solo --before "<before.sfs>" --after "<after.sfs>"

To see what a save still remembers about a mod you removed, list the quests. The --data option makes it warn about quests whose plugin is gone, and --details lists each quest's stages and objectives.

Command Prompt
sf-save-reader quests "<save.sfs>" --data --details

Before you share any output, add --redact. It hides your character name, Windows user name, computer name and profile folder. Plugin names, form IDs and quest names stay.

Command Prompt
sf-save-health check "<save.sfs>" --plugins "%LOCALAPPDATA%\Starfield\Plugins.txt" --redact

Part 2: Make a good bug report

First turn on Papyrus logging. In Documents\My Games\Starfield\StarfieldCustom.ini, add these lines, then restart the game:

[Papyrus]
bEnableLogging=1
bEnableTrace=1
bLoadDebugInformation=1

Play until the problem happens, then quit the game. Run the collector by double-clicking Collect-StarfieldTestLogs.cmd, or from PowerShell:

PowerShell
powershell -ExecutionPolicy Bypass -File .\Collect-StarfieldTestLogs.ps1 -Note "short description"

It writes one zip into Documents\StarfieldLogs. To include a before and after pair of your two newest manual saves, add -SavePair. To hide your Windows user name, computer name, user folder and Steam account number in the copied text files before you send the zip, add -Redact. Saves, screenshots and file names are left as they are.

PowerShell
powershell -ExecutionPolicy Bypass -File .\Collect-StarfieldTestLogs.ps1 -Note "short description" -Redact

Now read the zip with papyrus-log-check and its three starter rule files, which explain the game's common Papyrus error lines.

Command Prompt
python -I papyrus_log_check.py "<StarfieldLogs zip>" --rules rules\papyrus-runtime-errors.logrules.json --rules rules\papyrus-scripts-and-properties.logrules.json --rules rules\papyrus-saves-and-load.logrules.json

Finally, open the zip and look inside before you post it anywhere. Without -Redact, the files can hold your Windows user name and computer name.

Part 3: Patch day

After a game or Starfield Script Extender (SFSE) update, ask which of your SFSE plugin DLLs still load.

Command Prompt
.\sf-patch-day.cmd dlls

It gives each DLL a verdict: WORKS, NEEDS ADDRESS LIBRARY, MAY FAIL, NEEDS NEWER SFSE, LOCKED, NOT AN SFSE PLUGIN or UNREADABLE. It also shows the game version, the SFSE version for it and the Address Library file. For each SFSE plugin it also prints a framework line that says whether the plugin was built on CommonLibSF (a large C++ library for Starfield plugins), on plain SFSE, or "can't tell", with the evidence that decided it. It reads the DLL's bytes and never loads or runs the DLL, and the verdicts and exit codes are the same as before (sf-patch-day 0.3.0). You can give it a zip (a download you haven't installed yet) or a folder instead.

If you build a mod, drift tells you whether an update changed what your mod relies on. Release a mod covers it.

Part 4: Look things up

StarfieldVoiceTool lists every voiced line in Starfield and your mods. Open the window:

Command Prompt
StarfieldVT.exe

For bulk exports, always list first. --list writes nothing and shows what would be exported.

Command Prompt
starfieldvt-export voices --out voice-out --search "captain" --list

Example

You remove a mod and wonder whether your save still depends on it. Make a manual save before you remove it and another after you remove it and load the game once. Then run sf-save-health solo --before ... --after .... The report lists only what changed between the two saves.

Reading the results

ToolExit codes
sf-save-health0 healthy. 1 warnings or notes only. 2 at least one problem. 3 could not check.
sf-save-reader0 done. 1 done with warnings. 2 usage error. 3 error (unreadable, not a save, unsupported version).
sf-log-collector0 zip made. 1 the game was running and you declined. 2 error, nothing zipped.
papyrus-log-check0 no rule failed. 1 at least one FAIL. 2 bad arguments or unreadable input.
sf-patch-day dlls0 all work. 1 some need Address Library, may fail, need a newer SFSE, or SFSE is missing. 2 some are locked, or the install is Game Pass. 3 could not read.
starfieldvt-export0 done. 1 some failed. 2 bad command line. 3 no Data folder. 4 could not run (close the window).
  • Exit 2 from sf-save-health is normal after you remove a mod. It means problems were found, not that the tool failed. Only 3 means the check did not run.
  • Exit 0 does not mean a save is safe. Read the last lines of the report, which say what was not checked.
  • Some rules are heuristics. The quest-state and save-bloat rules can raise false alarms.
  • papyrus-log-check marks each rule PASS, FAIL or NOT SEEN. NOT SEEN usually means that feature wasn't tested. The report is a reading aid, not a verdict.
  • Game Pass. sf-patch-day dlls exits 2 and says so, because SFSE doesn't support Game Pass.

When PMT isn't enough

By design

The save tools read only saves from Starfield 1.16.244 (save version 153). Newer saves exit 3 until the tools are updated.

By design

Game Pass saves must be exported first with a third-party tool. The READMEs name HarukaMa's starfield-xgp-import and Z1ni's XGP-save-extractor.

Not in PMT yet

Papyrus script data in saves, such as orphaned scripts and stuck stacks, isn't checked. The report says so.

Note

Patch day doesn't watch the Creations you depend on, unless you list them in a drift mods file.

Note

PMT runs on a PC. For console saves, no PMT tool reads them.

Warning

Logs, reports and zips can hold your Windows user name, computer name and folder paths. Read them before you share them, and never share a save you haven't redacted.
