Part 1: For modders

More tools for modders

Do this with an agent

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

Five more tools help with the details of modding. sf-papyrus-ref looks up Papyrus names offline, sf-pex-tools compares compiled scripts and reads BA2 archives, sf-cut-check finds records nothing uses, BuildKit writes plugins from C#, and StarfieldVoiceTool finds and exports voice lines. All of them only read your files, except BuildKit, which writes your own plugin.

What you need

  • sf-papyrus-ref 0.2.4, sf-pex-tools 0.1.0 and sf-patch-day (which uses sf-pex-tools): Python 3.9 or newer, with no other packages. sf-cut-check 0.2.0 and StarfieldVoiceTool 0.10.0 are Windows programs. BuildKit 0.5.0 is a C# library that needs the .NET 9 SDK. Install them as in Getting started.
  • The free Steam "Starfield Creation Kit" for sf-papyrus-ref's signatures. It provides Tools\ContentResources.zip.
  • Your setup. Steam is found automatically by all of these. For Game Pass, pass the Data folder (<drive>:\XboxGames\Starfield\Content\Data). Under Vortex or Mod Organizer 2 (MO2), unpack the CK sources into a folder and pass --sources to sf-papyrus-ref.

sf-papyrus-ref

lookup answers, in about a tenth of a second, "does this Papyrus function exist, on which script, and is it safe on Xbox?" Exit 0 means found and exit 1 means not found, with near matches.

Command Prompt
sf-papyrus-ref lookup Debug.Notification --no-local

check reads your .psc or .pex files and reports BetaOnly calls (error), DebugOnly calls (warning, or error with --creations) and latent calls inside While loops (warning). Exit 0 means no errors (warnings are allowed), and exit 1 means at least one error. With --creations, Debug.Trace, Debug.Notification and Debug.MessageBox are warnings, because consoles ignore them, and any other DebugOnly call, such as Debug.QuitGame, is an error. You don't need --allow for the usual debug-switch pattern. Quest functions such as Quest.SetStage and the events of ReferenceAlias are on the shipped list, and lookup says "The official wiki has no page for this name" for them.

Command Prompt
sf-papyrus-ref check Scripts --creations

build-local reads the CK's scripts on your own PC once, and later lookups give exact signatures.

Command Prompt
sf-papyrus-ref build-local

html builds a browsable website of the CK's scripts, about 1,700 of them, in about ten seconds. It is for you only.

Command Prompt
sf-papyrus-ref html --out <folder>

mcp starts a read-only MCP server, which lets an AI agent look names up instead of inventing them. In Claude Code:

Command Prompt
claude mcp add sf-papyrus-ref -- python -I <folder>\sf_papyrus_ref.py mcp --quiet

sf-pex-tools

pex_compare.py compare tells you whether two compiled scripts do the same thing even when their bytes differ. Use it to see whether a recompile changed anything. Each side can be a .ba2, a folder or a .pex.

Command Prompt
python -I pex_compare.py compare <A> <B>

ba2_extract.py lists, extracts and compares the files in BA2 archives.

Command Prompt
python -I ba2_extract.py list <archive>
Command Prompt
python -I ba2_extract.py extract <archive> <outdir>
Command Prompt
python -I ba2_extract.py diff <A> <B>

A rebuilt script always shows as changed in ba2_extract.py diff, so use pex_compare.py for scripts.

sf-cut-check

On your own plugin, scan --plugin reports the records it adds but nothing uses. The first run scans the official files and saves the result, and later runs take seconds. It ends with a RESULT: line.

Command Prompt
sf-cut-check scan --plugin MyMod.esm

why shows the chain of records behind one verdict. Give every record in one call, because it reads all plugins on every run.

Command Prompt
sf-cut-check why <FormID:Plugin.esm or EditorID>

Orphaned and Unreferenced mean "nothing in the plugins uses it". They are not proof that a record is dead.

BuildKit

BuildKit is the C# library under sf-mod-build. A code builder uses these parts.

PartWhat it does
GameDataOpens masters from the Data folder, and extra folders searched first. Get<T>(editorId) finds a record.
Plugin.NewStarts a plugin, as light, medium or full, with author and description.
PluginWriter.WriteWrites the plugin, then runs the sf-mod-check gap check if it finds the tool.
IdLock.ApplyKeeps FormIDs stable between builds, in ids.lock.json.
GameplayOptions.DebugMakes the "Show Debug Messages (PC only)" option.
Messages.Hud, Messages.BoxOn-screen text that works on Xbox and PlayStation.
Effects, Quests.New, DialogTopics, LocalizedEffects, a quest shell, dialogue subtype names, and localized text.

BuildKit works only with Mutagen 0.54.4, which must be the only Mutagen version in your project. It doesn't compile Papyrus, pack BA2 archives or make zips. sf-mod-build does that.

StarfieldVoiceTool

StarfieldVoiceTool lists the voiced lines in Starfield and your installed mods, lets you search the text and save a line as a .wav. Start StarfieldVT.exe for the window. For bulk exports use starfieldvt-export, and run it with --list first, which is a dry run that writes nothing.

Command Prompt
starfieldvt-export voices --out <folder> --plugin Starfield.esm --search "text" --list

Close the window before a voices run that needs the search index. Exported audio is the game's or the mod's content, so share it only as its license allows.

Reading the results

  • sf-papyrus-ref check. Treat [name only] findings as less certain. Run build-local for exact matches. The Papyrus compiler is the final judge.
  • sf-pex-tools. Output is same, DIFFERENT (with a diff), ONLY IN first or second, UNREADABLE or DUPLICATE. pex_compare.py exits 0 when all are equivalent, 1 for differences, and 2 when unreadable.
  • sf-cut-check. Exit 1 means scan --plugin found Orphaned or Unreferenced records, or why found no record. Exit 2 means it could not run.
  • starfieldvt-export. Exit 0 is all written or kept. Exit 1 is some failures. Exit 4 means the window holds the search index.

When PMT isn't enough

Warning

Never share the html site, the local cache or extracted game files. They hold Bethesda's script text and files from your own install. Keep them out of repositories, releases and messages.

By design

sf-papyrus-ref doesn't cover Starfield Script Extender (SFSE) functions, and no PMT tool decompiles scripts. Champollion does. See the other free tools.

By design

StarfieldVoiceTool only browses and exports existing lines. It can't create, record or add voice lines to a mod. That is Creation Kit work, plus your own recordings.

For CK and xEdit authors

Use lookup and check while you write scripts in the CK, pex_compare.py to see whether a recompile changed anything, and sf-cut-check scan --plugin to find records you added and never used.

For code builders

All of the above, plus BuildKit. Look up every Papyrus name with sf-papyrus-ref before you write it, keep the Mutagen pin, and run sf-cut-check scan --plugin on each build.
