Part 1: For players

Find conflicts and build a patch

Do this with an agent

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Summary

sf-mod-check conflict shows which records two or more of your mods change, and sf-mod-check patch can build a local patch for your own game that picks a winner. The patch holds other authors' data, so it is for your game only and must never be published. Quests, dialogue and finer merges still go to xEdit.

What you need

  • sf-mod-check 0.17.0, installed as in Getting started. It needs the game's Data folder for masters. The Steam default path is found by itself. For Game Pass, add --data "<drive>:\XboxGames\Starfield\Content\Data".
  • Your load order. By default the commands read the game's own Plugins.txt.
  • Your setup. Vortex deploys mods into the real Data folder, so the commands work as they are. Under Mod Organizer 2 (MO2), add --mo2 "<instance folder>" (and --profile "<profile name>" if you don't use MO2's selected profile) to conflict, patch and find. They need sf-mod-check 0.16.0 or newer.
  • A backup. The patch is a new plugin and changes nothing else, but back up your load order before you add it.
  • Enough memory. The tool can stop with --max-memory if a run grows too large. Never run check on Starfield.esm, which needs over 30 GB of RAM.

Steps

What a conflict is

A record conflict happens when two mods change the same record, for example the same weapon or the same item. The mod that loads later wins, and the other mod's change is lost. Many conflicts are harmless. Some are not.

1. Run the conflict report

Command Prompt
sf-mod-check conflict

To choose where the report goes, add --out:

Command Prompt
sf-mod-check conflict --out conflict-report

If the run is too large for your PC, limit its memory (the number is in gigabytes):

Command Prompt
sf-mod-check conflict --max-memory <GB>

The tool writes report.html, report.md and conflicts.json. Open report.html in your browser.

Under MO2, give it your instance. It reads the profile's load order and looks for each plugin, archive and loose file in MO2's Overwrite folder, then in each enabled mod from the top of modlist.txt down, then in Data, the way MO2 builds its virtual Data folder.

Command Prompt
sf-mod-check conflict --mo2 "<instance folder>" --profile "<profile name>"

This was tested on made-up MO2 folders, so the first time, check that the report's load-order line reads MO2 profile <name> (<folder>), <n> active entries and read its load-order problems. --mo2 doesn't go with --plugins.

2. Let sf-load-order rate the conflicts

sf-load-order runs sf-mod-check for you and rates the conflicts in its own report. The load order page shows how to run it.

Command Prompt
.\sf-load-order.cmd

3. Build a patch

patch makes a local plugin, ConflictPatch.esm, plus patch-report.md and patch-sources.json. By default it builds from your whole load order.

Command Prompt
sf-mod-check patch

The patch and its reports go into a folder called sf-mod-check-patch in the current folder, unless you give --out.

To patch only some plugins, name them, separated by commas. Each one must be active in your load order, or the run stops with exit 2 and says that plugin isn't active.

Command Prompt
sf-mod-check patch --only MyMod.esm,OtherMod.esm

To pick which plugin wins a record, give the record's FormKey, an equals sign and the plugin, as in the example below (064F3C:Starfield.esm is the record and OtherMod.esm the plugin that should win). To pick one field only, put the field name after the FormKey: --pick 064F3C:Starfield.esm:Value=OtherMod.esm. You can repeat --pick. patch-report.md prints ready-made --pick lines for the records it found, so you can copy them. The plugin you pick must be active in your load order.

Command Prompt
sf-mod-check patch --pick 064F3C:Starfield.esm=OtherMod.esm

4. Load the patch last

Read patch-report.md, then install ConflictPatch.esm with your mod manager like any other mod, and put it at the end of your load order. Under MO2, add the patch as a mod of its own: choose Create empty mod, copy the patch into the new mod's folder, enable it, and put the patch at the end of the plugin list. With --mo2, --out may not be an MO2 mod or Overwrite folder. Then run .\sf-load-order.cmd again to confirm the order.

5. Check the patch again after any change

A patch is built from the mods you had when you made it. After you add, update or remove a mod, ask whether it is still current. Give the path of the patch you installed, for example the copy in your Data folder or in its MO2 mod folder.

Command Prompt
sf-mod-check patch check "<path to>\ConflictPatch.esm"

patch check compares the patch with your load order, so run it once the patch is installed and active. For a patch that isn't active, sf-mod-check (0.16.2 and later) prints a patch-off NOTE and RESULT: UP TO DATE (the patch isn't in the load order; nothing was checked), so read the whole line, not only the words UP TO DATE.

Look at one record

find shows one record: the plugin that defines it, the plugin that wins it, the other plugins with a copy, and the winning copy's main fields. Give an exact EditorID, a FormKey such as 01295A:Starfield.esm, or an 8-digit FormID as the game's console shows it. Add --type <SIG> to keep one record type, or --json for a script. The last line is RESULT: FOUND n record(s) (exit 0) or RESULT: NOT FOUND (...) (exit 1).

Command Prompt
sf-mod-check find <EditorID>

Example

Say two mods both change the damage of the same vanilla item. The conflict report lists that item once, names both mods, and shows which one wins. If you prefer the other mod's version, build a patch with --pick naming that mod for that record. Load the patch last, and the game uses your choice.

Reading the results

  • The report. report.html lists conflicts by record, with the plugins involved. conflicts.json holds the same data for other tools.
  • Patch check. The result line says RESULT: REBUILD when the patch is out of date. If the patch is current, the result says it is up to date. Rebuild after any change to the mods it was built from.
  • Exit codes. For conflict, a stop caused by --max-memory exits 3. For patch check, read the RESULT: line, not only the exit code. conflict exits 0 when it wrote a report, 2 when it couldn't run and 3 when it stopped at --max-memory. patch exits 0 when it wrote the patch (or had nothing to patch), 1 when reading the patch back found a difference (don't use that patch, and report it with a --log file), 2 when it couldn't run and 3 when it stopped at --max-memory. patch check exits 0 when the patch is up to date, 1 when something needs a rebuild or a look, and 2 when it couldn't check.
  • Rating. sf-load-order rates the conflicts it finds, so you can see which matter most.

When PMT isn't enough

Warning

A conflict patch holds other authors' data. Use it for your own game only. Never publish it, share it or upload it anywhere.

By design

A mod's ship change can't beat an official BlueprintShips- file, because that is an engine rule. No patch fixes it.

Not in PMT yet

patch doesn't build records inside quests or dialogue topics, and it can't merge fields beyond choosing a winner with --pick. The report lists those records so you can handle them in xEdit.
